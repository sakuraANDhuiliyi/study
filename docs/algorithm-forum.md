# 算法论坛与题目讨论

入口为 `/algorithms/forum`。算法练习列表有“算法论坛”入口，每道题的工作区新增“讨论”标签，可以直接查看该题的帖子或发表关联讨论。

## 可见范围

发布窗口要求明确选择范围，按钮会说明实际发布到哪里。范围发布后不可改变，编辑内容也不能顺便把机构帖子改成公共帖子。

- **公共社区**：所有已登录的平台用户可读，包括学生、教师、机构管理员及平台管理员。未登录游客不能访问。
- **本机构讨论**：仅当前学校 / 机构中的用户可读。切换到其他机构或个人空间后无法继续访问原机构帖子与回复。个人空间用户仅能向公共社区发帖。

两类帖子分别列表展示，支持搜索标题 / 内容、按提问 / 题解 / 交流和关联算法题筛选、分页。题目页面也分别展示公共与本机构讨论。

此次新增独立数据表，没有复制或公开原有课程讨论、聊天、用户学习记录。帖子使用数据库保存的随机“学习者·xxxxxxxxxxxxxxxx”别名，不能从公开的用户 ID 推算。公共社区与每个机构讨论区分别分配别名；同一讨论区内发帖和回复的别名保持一致，重启服务不改变别名。接口不返回别名映射、作者原始用户 ID、私有用户名、姓名、密码或机构 ID。别名不提供完全匿名保证，发帖者仍须自行避免在正文中公开私人资料。

迁移 27 会为历史帖子和回复分配新别名，原先根据用户 ID 生成的旧别名将不再显示；此前已经公开或保存的内容无法通过这次升级撤回。

## 操作与权限

学生需要 `learning.use` 才可发布、编辑自己的帖子或回复。其他身份需要 `communication.write` 才能发言；教师默认有该权限，管理员默认只有阅读和管理权限。

作者可编辑或软删除自己在当前机构身份下发布的内容，也可把自己的帖子标记为已解决。关闭的帖子不接受编辑或新回复。作者不能自行置顶或关闭帖子。

具有 `communication.moderate` 的机构管理员可以置顶、关闭 / 重新开放、标记解决以及软删除**自己机构发布的内容**，包括机构内用户在公共帖子中的回复。看到另一机构的公共帖子，不代表拥有其管理权限。具有 `communication.moderate` 和 `org.platform` 的超级管理员可以管理公共内容；其他机构的内部帖子仍不会因公共社区入口而对其开放。

帖子修改、管理、删除与回复提交都携带预期版本号。并发修改只允许一个版本生效；发生冲突时编辑器保留输入，并展示最新帖子，用户查看后可显式选择“基于最新版本继续编辑”。机构功能开关、会话撤销、角色权限变化及全机构禁言会在写入事务中再次检查。

## 内容与容量

正文按普通文本显示，可粘贴多行代码。HTML、脚本和 Markdown 标记均作为文字展示，不执行，也不通过 HTML 注入渲染。没有上传附件或从帖子中运行代码的入口。

- 标题最多 160 字符，帖子或回复正文最多 15,000 字符。
- 每个用户最多保留 100 篇发帖记录、2,000 条回复记录；软删除不重置数量。
- 每个用户每分钟最多 10 次论坛写入，每滚动 24 小时最多 200 次；发表、编辑、回复、删除和管理都计入。
- 列表默认每页 20 条，最多每页 50 条。

用户写入使用事务锁与审计记录，帖子状态修改及回复提交使用同一帖子锁，避免关闭期间新回复绕过校验。审计仅记录操作、范围、关联题目、版本号或状态字段，不记录帖子 / 回复正文。软删除保留审计与记录，但不再出现在正常列表、详情或回复接口。

## 本地验证

2026-10-09 的模块验收通过：9 项单元测试、13 项真实 HTTP 测试（12 个业务子项及父测试）、8 项浏览器契约测试。随机别名回归覆盖持久保存、讨论区隔离、并发分配及批量查询；浏览器使用新的 16 位别名验证发布范围、纯文本安全、编辑冲突及移动布局。浏览器契约使用本地 API fixture，不代表真实数据库中的浏览器联调；HTTP 测试实际访问独立的本地 review API 和数据库。

静态类型检查与 lint 覆盖前后端模块。`tests/algorithm-forum.unit.test.ts` 检查严格参数、长度、版本、别名及可见性 / 管理规则；`tests/algorithm-forum.integration.ts` 在隔离 review 数据库建立临时机构、个人用户及帖子，执行真实 HTTP 校验后清理；`tests/browser/algorithm-forum.spec.ts` 使用本地 API fixture 验证发布范围、纯文本安全、回复、冲突编辑与移动布局。

运行接口测试前，确保 review 数据库已应用全部迁移（包括 27），并构建 API。通过实际 dotenv 加载器运行测试：

```sh
DOTENV_CONFIG_PATH=.data/review.env node --import tsx --test --test-concurrency=1 tests/algorithm-forum.integration.ts
```

`prisma migrate deploy` 本身不识别 `DOTENV_CONFIG_PATH`；迁移 review 数据库时需由 dotenv 包装进程，或显式把 review 的 `DATABASE_URL` 传给 Prisma，避免意外迁移默认 `.env` 中的数据库。
