# 安全复查与优化（2026-10-08）

本轮在独立 PostgreSQL 审查库和 API 3002 上执行。测试使用真实 HTTP、文件下载、WebSocket 和数据库锁；原演示库未用于回归。下面区分已复现的问题、实际优化和仍待验证的范围。

## 已修复的问题

| 问题                                       | 修复前证据与影响                                                   | 修复                                                                       |
| ------------------------------------------ | ------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 学生尚未正式提交的作业附件可被教师下载     | 持有附件 ID 的当前课程教师请求返回 200；草稿应仅本人可见           | 读取他人文件必须存在正式提交引用，并再次验证当前课程与批阅权限             |
| 课程上传范围被误当作已经发布               | 学生未发帖的课程附件对教师可见                                     | 按实际课时、作业或讨论引用授权；草稿、开放时间、隐藏状态及治理权限分别处理 |
| 开考与取消考试／撤销资格发生竞态           | 在外键写入处暂停开考请求，撤销完成后仍插入有效答卷                 | 生命周期操作使用同一事务锁；取消已有作答中的答卷                           |
| 可预报版本号绕过禁止返回上一题             | 请求基于旧位置校验，但使用预报的新 revision 成功将位置回退         | 在答卷行锁内重新读取并校验位置、资格、状态和版本                           |
| 取消旧考试后可复用已泄露答案的题目         | 学生已可查看旧答案，同题仍可发布为新保密考试                       | 检查历史答卷，不因取消考试而忽略已暴露的题目                               |
| 功能关闭策略可被大小写路由绕过             | 关闭练习后 `/api/practice` 为 403，`/api/Practice` 为 200          | 功能路由、API 缓存头和 SPA 排除路径统一按大小写无关匹配；补上收藏写入口    |
| 作业附件可跨课程错绑                       | 课程 B 附件被课程 A 作业创建接口接受                               | 新增、修改和发布时验证文件实际课程；不扩展学生文件跨用途共享               |
| 作业发布未复查停用题目                     | 创建草稿后停用题目，仍可发布                                       | 在题目锁内重新校验固定版本的可用性和共享权限                               |
| 班级统计混入其他班学生                     | 同课程的 A 班筛选中出现 B 班学生及成绩，导致平均分和导出错误       | 课程与班级成员共同限定统计范围，明细、提交率、班级比较和 CSV 保持一致      |
| 历史任务使新待办消失                       | 超过 100 条过期任务排在前面时，即将截止的任务不显示                | 将有效时间条件放到数据库分页前；补稳定排序和跨首页六门课程的名称查询       |
| 合法作业附件被错误拒绝                     | 个人文件用作已开放作业说明、或同文件具有多个有效提交引用时返回 403 | 按所有当前授权业务引用查找，不任意采用第一条引用                           |
| 非敏感模板权限移除后无法恢复               | 超管有模板维护权但不持有教师业务权限，无法恢复已移除权限           | 在固定角色上限内允许非敏感模板维护；本人模板、超上限和敏感授权限制保持有效 |
| WebSocket 鉴权期间断开造成会话／定时器残留 | 用可控异步鉴权确定性复现生命周期交错                               | 在异步边界复查连接；合并重叠权限查询，并限制每用户和进程的连接数量         |

原始复现日志保存在 `.data/*security-before.log`。模块细节见 [认证与管理复核](auth-security-review.md)、[评测复核](assessment-security-review.md)。数据库中由测试创建的记录留在独立审查库，不能作为演示成绩。

## 依赖与性能优化

- 全量依赖扫描发现 5 个受影响依赖节点，包含开发工具链的传递依赖；原来只扫描生产依赖会漏掉这些节点。这不等于已经证实该站点存在远程命令执行入口。
- 将 `concurrently` 使用的 `shell-quote` 固定到 1.12.0，修复公告涉及的命令拼接问题；[上游公告](https://github.com/advisories/GHSA-pqg4-j6r4-53mv)列出的修复版本为 1.11.0 起。
- `braces` 3.0.3 的[递归耗尽公告](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)尚无补丁。移除引入它的 nodemon 开发链，改用已有 Node 22 的原生 watch；已实际验证启动与修改后的自动重启。
- 更新后 `npm audit` 覆盖开发、生产依赖均为 0 项已知漏洞。CI 增加 high/critical 门禁，并在专用 `review` 数据库执行安全回归。
- 按 [ECharts 官方按需导入方式](https://echarts.apache.org/handbook/en/basics/import/)只注册折线、柱状、坐标轴、图例、提示框和 Canvas 渲染器，继续延迟加载。生产图表包从 1135.53 kB 降为 537.59 kB；gzip 从 382.15 kB 降为 183.56 kB，约减少 52%。主应用包体积基本不变。
- 分析查询不再读取统计用不到的完整作答 JSON；题目版本去重、一次读取并用 Map 聚合，替代逐条反复查找和按每题扫描全部作答。
- 讨论附件的回复引用改为数据库 `EXISTS` 查询，避免读取全部回复 ID 后再次查询。WebSocket 对同一连接合并重叠的权限复查，默认每用户 20 个、单进程 2000 个连接，可配置。

## 验证与复现

新增回归使用 `npm run test:security`，按文件顺序执行，避免角色模板变更与其他用例相互干扰。需要显式指定隔离数据库配置、`TEST_BASE_URL` 与 `TEST_API_URL`，并让请求 `APP_ORIGIN` 与服务配置一致。评测锁测试要求数据库名称包含 `review`。

实际结果：单元 **40/40**，原业务集成 **12/12、10/10、11/11**，新增安全回归 **18/18**，浏览器 **7/7**，均无失败或跳过；API/Web 构建、类型检查、ESLint 通过。

最终运行结果见 [本轮验证摘要](verification/security-review.json)。完整日志保存在本机 `.data/security-*.log`，类型、静态检查、生产构建与浏览器交互分别验证。

## 仍有价值的后续优化

1. 在目标 Docker/Linux/HTTPS 环境执行发布验收；本机没有 Docker 引擎，本次不能宣称容器或 CI 已运行通过。
2. 大规模历史数据可进一步采用数据库聚合或分页报表；本次优化了读取字段和聚合查找，没有证明千人同时考试或多年数据的容量。
3. 登录限流及 WebSocket 上限是单进程控制。多实例部署需网关限流、明确的任务租约所有权与故障恢复压力测试。
4. 视频可增加授权 Range 分段读取；文件安全可按部署需求接入病毒扫描，存储接口可接入对象存储。

这些结果仅代表已执行路径和断言通过，不能保证所有接口、输入组合及并发交错都不存在漏洞。
