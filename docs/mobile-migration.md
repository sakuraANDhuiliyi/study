| ---------------------------------------------------- | ---------------------------------------- | ---------------------------------------------------------- |

## 迁移顺序与依据

[Moodle 官方 App 能力](https://docs.moodle.org/en/Moodle_app_features)将课程、待办、活动完成、成绩、交流与日历作为移动学习的主要路径。结合本项目已有后端，实施顺序为学习计划 → 作业与成绩反馈 → 视频及附件 → 考试与通知 → 练习/算法/编程/专业学习 → 教师与管理功能。该顺序是本项目的实施判断，不表示表中的未完成项已开发。

视频使用 [Expo 56 对应的 expo-video 文档](https://docs.expo.dev/versions/v56.0.0/sdk/video/)评估；文件使用 [Expo 56 FileSystem 文档](https://docs.expo.dev/versions/v56.0.0/sdk/filesystem/)评估。新增依赖须匹配现有 SDK，不能为了显示网页而把后台 bearer 凭据传给不受控浏览器或第三方。

## 一致性要求

- 逐条扩展原生接口许可，继续复用业务权限与数据库事务；网页 Cookie/CSRF 与原生 bearer 不混用。
- 选课撤销、账号停用、机构开关、成绩发布、考试截止和文件授权由服务端重新确认。
- 草稿冲突显式处理；网络断开后先查询确认提交结果，不能无条件重复创建或交卷。
- 真机、蓝牙、校园网/蜂窝网络与 TURN 验收独立于模拟器测试；合成摄像头的成功不能替代硬件验收。
- 本地测试与 HTTPS 预览连接不同数据库，本地演示账号不会自动同步至服务器。
