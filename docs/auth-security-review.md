# 认证、管理与课程权限复核（2026-10-08）

本轮在独立审查数据库及 API 3002/3003 上验证，没有修改演示数据库。覆盖 `auth`、`admin`、`courses` 的角色模板、独立敏感授权、机构隔离、成员权限撤销和人员导入。

## 已修复的问题

### 功能开关可被路由大小写变体绕过

旧版 `AuthService.checkFeature` 对请求路径执行大小写敏感匹配，而 Express 接受大小写不同的路由。当机构配置 `practice=false` 时，`GET /api/practice` 被拒绝，`GET /api/Practice` 仍返回 200 和练习列表。

修复将功能范围匹配改为大小写无关，并将原来遗漏的 `PUT /questions/:id/favorite` 收藏写端点纳入练习开关。主任务同时修复了 API 前缀的缓存头和 SPA 回退判断，避免 `/API/...` 被错误返回 HTML。

回归覆盖练习、错题、收藏、讨论和会话的大小写变体，关闭后均返回 403；正常身份接口保持可用。旧版复现记录位于 `.data/auth-security-before.log`。

### 非敏感角色模板权限移除后无法恢复

原模板维护要求新增权限同时存在于操作者当前有效权限中。超级管理员具有 `roles.manage`，但不具有 `course.manage` 等教师业务权限，造成可移除这些模板权限，却无法恢复的状态。

修复允许持有 `roles.manage` 的操作者恢复目标角色固定上限内的非敏感权限，同时继续执行：

- 禁止修改操作者自身持有的角色模板。
- 目标权限不得超出 `roleDefinitions` 固定上限。
- 新增敏感模板权限仍要求操作者已取得相应独立权限；保留已有敏感模板项不会扩大有效授权。
- 敏感权限在使用时仍须同时满足当前角色模板及有效独立授权。

回归实际移除和恢复教师 `course.manage`，旧会话在下一次请求立即反映变化；无独立授权时恢复新增敏感权限、超角色上限及本人模板修改均被拒绝。测试结束恢复原模板。

## 验证结果

新增 `tests/auth.security.integration.ts`，显式要求 `TEST_BASE_URL`，不会默认使用演示服务：

```sh
DOTENV_CONFIG_PATH=.data/review.env TEST_BASE_URL=http://127.0.0.1:3003 \
  node --import tsx --test tests/auth.security.integration.ts
```

四项 HTTP/真实 PostgreSQL 测试全部通过（1.62 秒）：

1. 关闭功能的大小写路由和收藏写入均被拒绝。
2. 拒绝自提权、跨机构账号更新、自授敏感权限；撤销敏感授权立即生效，角色调整使旧会话失效。
3. 非敏感模板权限可在固定上限内恢复，敏感新增限制保持有效。
4. 非法导入整批不落库，返回数据不含明文密码；跨机构课程引用、学生完整名单访问、已撤销成员访问和已停用教师会话均被拒绝。

结果记录位于 `.data/auth-security-results.log`。API TypeScript 检查及本轮涉及模块、测试的 ESLint 检查均通过。

本轮没有修改课程控制器或数据库结构；这些已覆盖的课程权限路径未发现需要修复的问题。此结果是定向回归证据，不代表对全部接口、并发交错或所有输入组合进行了穷尽验证。
