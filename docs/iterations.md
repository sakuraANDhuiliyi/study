# 持续迭代与完整验收

从 2026-10-09 起，本项目按用户要求逐项迭代。每轮只完成一个可独立使用的功能；完成实现、解决所有测试失败、记录验收结果并推送远程后，才开始下一轮。用户要求停止时，结束当前工作并暂停续跑。

优先补充学生实际学习所需的能力：算法练习、专业实验、学习计划、笔记与复盘，以及与这些功能对应的机构管理。新增专业内容应有自己的学习目标、原理、输入、示例和可复核的结果，避免仅增加空页面、相同模板的改名副本或没有依据的能力评分。

## 每轮完整流程

安装项目锁定依赖，并使用项目支持的 Node.js 22 或 24。测试数据库须为本机单独的 PostgreSQL review 库，连接串及开发种子密码保存在未纳入 Git 的环境文件中。运行脚本之前关闭本轮自己启动的旧测试服务；脚本遇到被其他进程占用的端口会拒绝继续，不会终止它们。

```sh
node --env-file=.data/algorithms-review.env scripts/verify-iteration.mjs
```

默认完整流程包含：

1. Prisma 客户端生成、全部数据库迁移和幂等开发种子。
2. API/Web 类型检查、ESLint、所有单元测试、生产构建和依赖审计。
3. 可信仓库算法参考程序的 Python、JavaScript、C++、Java 四语言编译／执行验证。
4. 编译后 API 与静态网页的真实启动、数据库健康检查和浏览器 CSP。
5. 完整原业务端到端测试，以及自动发现的全部 `tests/*.integration.ts`，包含账号、评测、交流、安全、日历、笔记、AI、算法和专业功能。
6. 新建临时数据库的迁移、重复种子、受限生产初始化和角色登录验收。
7. 已授权接口的本地性能烟雾测试，要求所有请求成功；这不是生产容量承诺。
8. 全部浏览器用例，包括真实 API 流程、界面契约、错误恢复和移动端布局。跳过、意外取消、空集合或失败都不会被标为完整通过。

脚本使用两个自身启动的编译后服务：接口为回环地址的 3002，网页为 `http://localhost:3003`；两者使用相同的网页 Origin。3031–3037 留给独立数据库集成用例。服务、临时配置和子进程由脚本在结束时清理；现有 review 库不会被删除或重置。

每轮在 `.data/iteration-*` 保存结构化报告。发生失败时保存权限受限的脱敏诊断日志，记录失败阶段后修复，再重新执行完整流程。只有完整流程通过后才提交和推送，报告摘要另保存到 `docs/verification/`。真实 `config.yaml`、环境文件、数据库目录和部署凭据保持在 Git 之外。

`--profile=ci` 明确选择只验证 Python/JavaScript 的参考程序，供没有 C++/Java 环境的 CI 使用；它会在报告中标记覆盖范围，不替代本机默认四语言完整验收。实际外部 Judge0、AI 服务和目标 Linux/HTTPS 部署仍需要服务地址、凭据及目标环境，未执行时单独记录。

## 第一轮：专业学习目标

学生可以为一个学习模块设置目标数量和可选的截止日期，在专业学习中心管理目标，或从模块工作台直接创建。

- 普通模块按目标建立后、本人当前空间中标记为 `COMPLETED` 的练习记录计数。把记录改回继续研究或删除记录后，进度相应减少；同一记录不会反复计数。
- 算法模块按目标建立后正式提交通过的不同题目计数。样例运行、自定义输入和同一题目的重复提交不增加题数。
- 完成表示已达到用户设定的数量，不代表掌握程度、专业评价或 AI 评分。截止日期按北京时间自然日解释，未完成且未归档的目标在日期过后显示过期。
- 可编辑、归档、恢复和删除目标。编辑使用版本校验；发生冲突时保留当前输入，读取最新内容并由用户核对后保存。删除目标不删除练习记录。
- 目标按账号与学习空间隔离。个人账号加入机构后使用机构空间的目标；返回原个人空间时恢复原来的目标。

接口仅供具有学习权限且功能开启的学生使用：

| 方法与路径                    | 输入与行为                                                             |
| ----------------------------- | ---------------------------------------------------------------------- |
| `GET /academics/goals`        | `status=active`（默认）、`archived` 或 `all`，返回 `{items}`           |
| `POST /academics/goals`       | `{moduleId,title,targetCount,dueDate?}`；日期为 `YYYY-MM-DD` 或 `null` |
| `PATCH /academics/goals/:id`  | `{revision,title?,targetCount?,dueDate?,archived?}`，至少修改一项      |
| `DELETE /academics/goals/:id` | `{revision}`，删除当前空间本人的目标                                   |

数量为 1–1000，标题最多 160 字符，日期限定真实公历的 2000–2100 年。每个学习空间最多保留 100 个目标，包含归档目标。未知模块、非法输入、旧版本或他人目标不会被静默接受；机构管理员和教师也不能查看学生的私人目标。

提交 `82bde26` 的 [远程 CI](https://github.com/sakuraANDhuiliyi/study/actions/runs/37821163484) 全部通过，包括 Node 22、PostgreSQL 17 环境下的构建、审计、接口集成及浏览器验收。

## 第二轮：专业实验记录与笔记导出

学生在“学习记录与笔记”页按模块和“已完成／继续研究”筛选自己的记录，并下载 CSV 总览或 Markdown 详细笔记。导出使用当前空间已经保存到服务器的数据，不限当前列表页；不会自动保存本机草稿、改变完成状态、重新计算实验或调用 AI。

- CSV 包含记录元数据、模块、完成状态和结果摘要，附 UTF-8 BOM，保留中文并防护公式前缀。默认导出匹配范围中的全部记录，最多 5000 条。
- Markdown 保留输入参数、完整持久化结果（包含表格与图表数据）和补充笔记，默认导出最新 20 条，最多 50 条。代码、SQL、矩阵、JSON 和个人文本按字面保存，避免文本中的 HTML、链接或围栏改变文件结构。
- 文件按创建时间倒序排列，界面明确显示请求数量与匹配总数；指定数量少于匹配总数时，只导出最新的指定数量，不截断单条正文。完整文件超过 8 MiB 时返回错误，用户可减少数量或收窄筛选后重试。
- 当前空间本人一分钟最多成功导出 5 次。仅学生本人具有学习权限且功能开启时可以导出；教师、管理员不能用此接口读取学生私人记录。审计只记录格式、筛选、条数和字节数，不保存记录内容。
- 网络错误会保留格式与数量选择；退出登录、切换账号或空间时会取消在途下载，不把旧空间文件放入新会话。下载成功表示浏览器已开始接收附件，不代表文件已经写入磁盘。

接口：

```http
POST /api/academics/records/export
Content-Type: application/json
x-csrf-token: 登录返回的当前令牌

{"format":"md","moduleId":"study-notebook","status":"COMPLETED","limit":20}
```

`format` 为 `csv`（默认）或 `md`；`status` 为 `all`（默认）、`DRAFT` 或 `COMPLETED`；`moduleId` 可省略；`limit` 为正整数，按格式执行上限。返回附件以及 `X-Export-Matched-Count`、`X-Export-Record-Count` 和 `X-Export-Truncated`，分别表示筛选匹配总数、实际导出数量及是否只导出了最新的指定数量。无匹配记录的 API 返回带表头或说明的空文件；界面会提示没有可导出的记录。

原列表接口 `GET /api/academics/records` 同步支持相同的状态筛选。此轮无需新增数据表；完整验收仍包含全部迁移与空库启动验证。

本轮初次全量验收为 503/504，通过的数据库、文件内容及其他浏览器用例保持有效；唯一失败暴露了验证脚本将 `NODE_ENV=test` 传给 Vite 构建，导致控件使用固定测试 ID。已把构建子进程单独改为 `NODE_ENV=production`，服务和测试继续使用隔离的测试环境；新增用例通过实际 Vite 编译器检查生产标记。下拉菜单验收同时等待关闭动画并排除隐藏控件，筛选与文件内容断言保持严格。修复后重新执行全部流程，再记录最终结果。

最终完整验收 32 个阶段通过：268 项单元测试、174 项真实数据库／接口测试、63 项浏览器测试，合计 505 项，零失败、零跳过。四语言 72 个参考程序的 572 组用例通过；空库迁移、重复种子、受限生产初始化和登录、生产网页构建及 CSP 验收通过；100 次本地并发请求零错误。真实下载文件经独立 CSV 与 Markdown 解析核对，超过页面数量的记录、完整笔记与实验数据、筛选、大小限制、取消、网络错误恢复和用户／空间隔离均通过。详见 [第二轮结构化验收记录](verification/iteration-002.json)。
